## 2. 프로젝트 개요

**나갈시간**: 요일별로 "어디에 몇 시까지 도착"만 입력하면, 열차 시간표 데이터로 탈 열차(환승 포함)를 골라 **기상·출발 시간**을 계산하고, 요일별 알람을 **휴대폰 캘린더(.ics)** 로 한 번에 보내 주는 웹 앱.

### 핵심 가치 (사용자와 여러 번 논의해서 다시 정한 것)
- 하루치 계산만 보면 머리로 하는 게 빠름 → **"계산"은 장점이 아님**.
- 진짜 장점 두 가지:
  1. **환승 열차까지 시간표로 골라 줌** (머리로 하기 귀찮은 부분: "07:57 타면 용산 몇 시, 1호선 몇 시 거 타지?")
  2. **알람 관리**: 수업 시간이 바뀌면 그 요일 도착 시간만 바꾸고 캘린더로 다시 보내면 끝 (지금은 알람 앱에서 요일 섞인 알람을 하나씩 고쳐야 함)
- 네이버 지도와 차이: 길찾기는 그날 한 번이지만, 나갈시간은 **요일별로 저장하고 알람까지 이어짐**.
- 사용자 원래 불편: 알람이 시간순으로만 정렬돼 요일별로 안 보임, 요일마다 다른 시간을 직접 계산해 알람 이름에 적어 둠.

### 사용자의 실제 통학 (테스트·데모 기준값)
- 집 → 가좌역 걷기 약 12분, 기상 약 06:25, 출발 07:45, 준비 약 80분
- **가좌 07:57 경의중앙선 용산행(K5301)** → 용산 08:10 → **1호선 08:16(K47)** → 온수 08:42 → 걸어서 학교(성공회대) 약 09:00
- 다른 경로: 버스 → 홍대입구 → 2호선 → 신도림 → 1호선 → 온수

### 지침(규칙)
- index.html을 file://로 열어도 동작해야 해서 ES 모듈·fetch 안 씀. `<script src>` 순서: data → time → calc → storage → ics → ui
- **실행 중 외부 API 호출 없음**. 시간표는 미리 받아 data/*.js에 넣음 (레일포털 담당자도 "1일 1회/배치로, 과도한 호출 시 불이익"이라고 함 → 발표 근거로 쓸 것)
- 시간은 내부에서 "자정부터 분"(정수), 화면에서만 "HH:MM"
- calc/time은 DOM 없는 순수 함수. 오류는 throw 대신 `{ ok: false, message }`
- 함수 이름 영어, 주석·화면 문구 한국어

### 데이터 모양
- 추천형 경로: `{ id, name, type: "trip", fromStation, toStation, walkMin, lastWalkMin, prepMin, slackMin, transferMin }`
- 직접 입력 경로: `{ id, name, type: "custom", walkMin, rideMin, prepMin, slackMin, customTimes }`
- 요일 계획: `{ mon: { routeId, arrive: "09:00" } | null, ... sun }`
- 계산 규칙(기존형): 탈 열차 = (열차 + rideMin) ≤ (도착 − slackMin)인 가장 늦은 열차, 출발 = 열차 − walkMin, 기상 = 출발 − prepMin, 알림 = 출발 − 10, 0 미만이면 +1440 하고 "전날"
- 월~금 weekday, 토 sat, 일·공휴일 sun (코레일 데이터는 sat=sun=휴일 시간표)

- 사용자: "이러면 그냥 내가 계산하는 게 빠르다, 쓸 이유가 없다" → **열차별 정차 데이터로 앱이 환승 열차까지 골라 주는 "열차 추천" 방식으로 전환**. 사용자는 출발역·도착역·걷는 시간·준비 시간만 입력.

TRIPS = { weekday: [...1389개], holiday: [...1159개] }

- 확인 예: K5301 가좌 477(07:57) → 용산 490(08:10), K47 용산 496(08:16) → 온수 522(08:42)

### 지원 노선 (최종 확정): 1호선, 2호선, 경의중앙선, 7호선
- 1호선·경의중앙선: 위 trips.js에 이미 있음 (코레일 엑셀. 경춘선·서해선도 같이 들어 있지만 필수 범위는 아님)
- **2호선·7호선: 레일포털 API로 받아 trips.js에 합쳐야 함** (아래)
- 환승역 예: 2호선↔1호선 신도림·시청, 2호선↔경의중앙선 홍대입구·왕십리, 7호선↔1호선 온수·가산디지털단지, 1호선↔경의중앙선 용산·서울역·청량리·회기
- 환승은 1번까지만 계산 (버스+2호선 경로는 버스를 "걷는 시간"에 넣으면 열차 환승 1번이라 가능)

### 레일포털 API (2호선·7호선)
- 사용자가 레일포털 "열차별 운행시각표"(trainUseInfo/subwayTimetable) 인증키 발급받음 (2027-11-09까지). **키는 사용자만 보관.**
- 응답 예(서울역 1호선 평일): `body: [{ railOprIsttCd, trnNo, dayCd, dayNm, stinCd, lnCd, arvTm: "064730", dptTm: "064800" }, ...]` 488건. 방향·행선지 없음 → **열차번호로 역들을 이어 붙이고 시간순 정렬**해서 trips를 만들 계획.
- 역사코드정보 엑셀(2026.07.11, 시트 "역사고유번호": RAIL_OPR_ISTT_CD, LN_CD, LN_NM, STIN_CD, STIN_NM)에서 **2호선(S1, 51개 역)·7호선(S1 42개 + 인천교통공사 IC 11개 역) = 104개 역** 선정
  - 나중에 넓히려면 같은 파일에서 수도권 585개 역(3~9호선, 신분당, 수인분당, 공항철도 등)도 고를 수 있음. 지금은 범위 밖
- `fetch_kric.py`: 사용자 맥에서 실행하는 1회용 다운로드 스크립트. 2·7호선 104개 역 × 평일(dayCd 8)·휴일(9) = 약 208번 호출, curl 사용, 1초에 1번, 약 5분, 중간에 끊겨도 이어받기, 키는 실행 시 입력. **위치: `tools/fetch_kric.py`**, 실행: 프로젝트 폴더에서 `python3 tools/fetch_kric.py`. 결과 `tools/kric_out/kric_timetable.json.gz` (.gitignore에 들어 있음, 아직 실행 전)
  - 모양: `{ "8|S1|2|0234": { line, name, rows: [[trnNo, arvTm, dptTm], ...] }, ... }`
  - **다음 할 일**: 이 파일을 받으면 → 같은 dayCd·운영기관·노선에서 trnNo별로 묶기 → 시각순 정렬 → stops 생성 → 역명 정규화(코레일 데이터와 환승역 이름 일치: 서울역, 홍대입구, 신도림 등) → trips.js에 합치기(토요일=휴일)
  - 주의: 2호선 순환 열차, 자정 넘는 시각(+1440), 데이터 없는 역, 파일 크기(브라우저 로딩)

## 6. 최종 기능 범위 (확정)

| # | 기능 | 완성 기준 |

## 8. 발표 예상 질문과 답 (초안)
- 왜 시간을 분으로? → "07:57"끼리는 빼기가 안 돼서 숫자로 계산하고 보여 줄 때만 바꿈
- 왜 throw 대신 `{ ok: false }`? → 앱이 멈추지 않고 화면에 이유를 보여 주려고
- 실시간 API는 왜 안 썼나? → 실시간은 "지금 몇 분 뒤 오나"만 알려 줘서 내일 아침 기상 계산에 쓸 수 없음. 레일포털도 과도한 호출 자제 요청
- 다른 사람도 쓸 수 있나? → 수도권 코레일 노선 전체(+레일포털로 지하철 확장), 없는 역은 시간표 직접 입력
- 열차 추천은 어떻게? → 도착 시간에서 거꾸로: 마지막 열차를 먼저 고르고, 그 열차를 탈 수 있는 첫 열차를 고름
